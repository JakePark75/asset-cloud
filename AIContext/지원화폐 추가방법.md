# 지원 화폐 추가 방법

## 현재 구조

현금은 실제 종목 티커와 충돌하지 않도록 내부 포지션 키를 사용한다.

| 사용자에게 보이는 통화 | 내부 positions.ticker |
|---|---|
| KRW | `__CASH_KRW__` |
| USD | `__CASH_USD__` |

`USD`는 실제 ETF 티커로 사용할 수 있으므로 달러 현금의 내부 키로 사용하면 안 된다. `USDKRW=X`는 현금 티커가 아니라 환율 데이터 티커다.

공통 키 생성과 판별은 `app/db.py`의 다음 함수가 담당한다.

- `cash_key(currency)`
- `cash_currency(ticker)`
- `is_cash_ticker(ticker)`
- `get_cash_currencies()`
- `get_cash_fx_map()`

현금 입력 UI는 `scheduler/config.json`의 `cash_currencies`에서 통화 목록을 읽는다.

```json
"cash_currencies": ["KRW", "USD"],
"cash_fx": {
  "USD": "USDKRW=X"
}
```

## 아직 환율을 지원하지 않는 통화 추가

현재는 실제 평가 환율이 연결된 통화만 `cash_currencies`에 넣는다. JPY/CNY를 단순히 UI에 노출하면 저장은 되더라도 원화 평가액을 계산할 환율이 없으므로, 환율 연결 전에는 목록에 추가하지 않는다.

환율 연결 전 구조를 시험해야 한다면 다음 내부 키가 만들어진다.

```python
cash_key("JPY")  # __CASH_JPY__
cash_key("CNY")  # __CASH_CNY__
```

단, 현재 평가 로직은 KRW와 USD 환율만 계산하므로 JPY/CNY를 실제 지원 목록에 넣기 전에는 평가 경로도 함께 확장해야 한다.

## JPY/CNY를 실제 지원하는 순서

### 1. 설정 추가

`scheduler/config.json`에 통화와 환율 티커를 추가한다.

```json
"cash_currencies": ["KRW", "USD", "JPY", "CNY"],
"cash_fx": {
  "USD": "USDKRW=X",
  "JPY": "JPYKRW=X",
  "CNY": "CNYKRW=X"
}
```

환율 제공처가 실제로 해당 심볼을 지원하는지 먼저 확인한다. 심볼의 가격 방향은 반드시 `1 외화 = 원화 금액`이어야 한다.

### 2. 환율 수집/저장 일반화

현재 USD 환율은 다음 경로에서 특별 취급된다.

- `scheduler/price_updater_rest.py`
- `scheduler/price_updater_ws.py`
- `scheduler/price_updater_common.py`
- `common/redis_store.py`
- `app/db.py`의 `get_usd_krw()`

새 통화 지원 시 `USDKRW=X`만 직접 비교하는 분기를 `get_cash_fx_map()` 기반 반복 처리로 바꾼다. Redis에는 예를 들어 다음처럼 통화별 환율을 저장한다.

```text
cash_fx:USD = 1,350.00
cash_fx:JPY = 9.20
cash_fx:CNY = 187.00
```

기존 `usd_krw` 키와 `get_usd_krw()`는 과거 데이터/화면 호환을 위해 당분간 유지할 수 있다. 새 공통 함수는 `get_currency_krw_rate(currency)` 형태로 두고, USD도 그 함수를 통해 읽도록 점진적으로 바꾼다.

### 3. 현금 평가 계산 일반화

현재 USD 환율을 직접 받는 평가 경로를 통화별 환율 조회로 바꾼다.

- `app/modules/accounts_DAL.py`
- `app/modules/accounts_helpers.py`
- `app/modules/portfolio.py`
- `app/modules/dashboard.py`
- `app/modules/export_DAL.py`
- `app/modules/asset.py`
- `app/utils/metrics.py`
- `app/utils/daily_snapshot.py`
- `app/utils/snap.py`
- `common/redis_store.py`

공통 계산 규칙은 다음과 같다.

```python
amount_krw = quantity * get_currency_krw_rate(currency)
```

KRW는 환율을 `1.0`으로 취급한다. 환율이 없거나 수집에 실패한 JPY/CNY는 `0원`으로 조용히 계산하지 말고 `미지원` 또는 계산 불가 상태로 표시한다.

### 4. 현금 입출금/매수·매도 연결 확인

현금 CRUD는 `app/modules/accounts_DAL.py`의 `add_cash()`와 `edit_cash()`가 `cash_key(cash_type)`를 사용한다. 새 통화는 별도 CRUD 코드를 추가하지 않는다.

매수/매도 시에는 종목 시장의 통화를 구한 뒤 다음처럼 현금 키를 계산한다.

```python
cash_ticker = cash_key(get_market_currency(market))
```

따라서 JPY 시장을 추가할 때는 `market_map`에 JPY 통화를 사용하는 시장을 등록하고, 해당 시장의 매수/매도 금액이 JPY 현금에서 차감/가산되는지 확인한다.

### 5. 화면 표시 확인

`app/modules/accounts_modals.py`는 `cash_currencies`를 읽어 현금 선택 목록을 만든다. 새 통화 표시명이 필요하면 `_cash_options()`의 라벨 맵에 추가한다.

예:

```python
labels["JPY"] = "JPY (엔화)"
labels["CNY"] = "CNY (위안화)"
```

화면의 내부 `data-ticker` 값은 `USD` 같은 사용자 통화 코드이고, DB의 포지션 값은 `__CASH_USD__` 같은 내부 키여야 한다.

## DB 확인 및 마이그레이션

현재 데이터는 다음과 같이 저장되어야 한다.

```sql
SELECT ticker, COUNT(*), SUM(quantity)
FROM positions
WHERE ticker LIKE '__CASH_%__'
GROUP BY ticker
ORDER BY ticker;
```

기존에 통화 코드를 직접 저장한 레거시 행이 발견되면, 실제 종목 행과 충돌하지 않는지 확인한 뒤 내부 키로 이전한다.

```sql
UPDATE positions
SET ticker = '__CASH_JPY__'
WHERE ticker = 'JPY';
```

실제 종목 티커와 현금 행을 구분하지 못하는 상태에서 일괄 UPDATE하지 않는다. 먼저 `tickers`와 `positions`를 조회해 해당 코드가 현금으로만 사용됐는지 확인한다.

## 변경 후 검증

1. Python 문법 검사

```bash
python3 -m py_compile app/db.py app/modules/accounts_DAL.py app/modules/accounts_helpers.py app/modules/accounts_modals.py
```

2. 현금 추가: KRW/USD가 각각 `__CASH_KRW__`, `__CASH_USD__`로 저장되는지 확인
3. 실제 `USD` 종목 추가: `positions.ticker = 'USD'`로 별도 저장되는지 확인
4. 계좌/포트폴리오/대시보드/엑셀의 현금 합계가 동일한지 확인
5. 매수·매도 시 해당 시장 통화의 현금만 변동하는지 확인
6. 환율 미지원 통화가 총자산을 임의로 0원 또는 큰 금액으로 왜곡하지 않는지 확인
